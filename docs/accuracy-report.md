# 자동 모드 정확도 분석 보고서

- 측정일: 2026-10-11 (v0.3.0 기준값)
- 대상: 자동 모드 판단 로직 (`AutoDetector`), 문장 맥락 모드, Ctrl+Space 변환 (`TypedSegment`)
- 원본 수치: [accuracy-results.json](accuracy-results.json) · 측정 코드: [tools/Evaluation](../tools/Evaluation/Program.cs)

## 요약

| 항목 | 한국어 글 | 영어 글 |
|---|---|---|
| 제대로 친 글을 **잘못 바꾸는** 비율 (단어당) | **0.002%** | **0.005~0.010%** |
| 잘못 바뀐 단어가 하나라도 생기는 문장 | 0.03% (약 3,000문장에 1번) | 0.09~0.17% (약 600~1,000문장에 1번) |
| 잘못된 모드로 친 단어를 **고치는** 비율 | **99.7%** | **91~92%** |
| 잘못된 모드로 친 문장이 **통째로** 고쳐지는 비율 (문장 맥락 모드 켬) | **98%** | **68~70%** |
| 영어 단어 + 조사 (`SNS를`, `email을`) 복원 | 92.7~92.9% | |
| Ctrl+Space로 문장 전체 변환 | 100% (키로 다시 칠 수 있는 문장 기준) | 100% |
| 비밀번호·아이디처럼 생긴 입력 | 변환 0% | |
| 속도 | 단어 하나 판단에 1µs 미만, 시작 시 0.4초, 메모리 약 70MB | |

한 줄로: **멀쩡한 글을 잘못 건드리는 일은 매우 드물고, 한국어를 영어 모드로 친 경우는 거의 다 고쳐진다.
영어를 한글 모드로 친 경우는 단어 10개 중 1개꼴로 남지만, 문장 맥락 모드가 그중 상당수를 잡아서 문장 10개 중 7개는 통째로 고쳐진다.**

## 측정 방법

### 시험 데이터: 사전을 만들 때 쓰지 않은 글

자동 모드는 단어 빈도 사전으로 판단하기 때문에, 사전을 만든 데이터로 시험하면 점수가 부풀려진다.
그래서 **사전에 전혀 쓰이지 않은** 라이프치히 대학 코퍼스(CC BY 4.0) 40만 문장으로 측정했다.

| 이름 | 내용 | 문장 | 단어 |
|---|---|---|---|
| 영어 뉴스 | eng_news_2024_100K | 100,000 | 200만 |
| 영어 위키백과 | eng_wikipedia_2016_100K | 100,000 | 209만 |
| 한국어 웹 | kor-kr_web_2015_100K (블로그·커뮤니티 등) | 100,000 | 172만 |
| 한국어 뉴스 | kor_newscrawl_2016_100K | 100,000 | 181만 |

사전은 자막·위키백과(2021~2023)·뉴스(2022)·ENABLE·Hunspell로 만들었으므로 출처와 연도가 겹치지 않는다
([DICTIONARIES.md](../tools/DICTIONARIES.md)).

### 실제 타이핑 흉내

- 문장을 앱과 똑같이 스페이스·`. , ? ! ; :`에서 끊어 단어로 나눴다.
- **제대로 친 경우**: 영어 단어는 영어 모드로, 한글 단어는 한글 모드로 쳤다고 보고, 하나라도 바뀌면 "잘못 바꿈"으로 셌다.
- **잘못된 모드로 친 경우**: 영어 단어를 한글 모드로(`hello` → `ㅗ디ㅣㅐ`), 한글 단어를 영어 모드로(`안녕` → `dkssud`) 쳤다고 보고,
  정확히 원래 단어로 돌아오면 "고침"으로 셌다. 대문자는 Shift를 눌렀다고 보고 그대로 유지돼야 성공.
- 숫자·따옴표·괄호가 붙은 단어는 앱이 원래 건드리지 않으므로 판단 대상에서 뺐다.

## 1. 멀쩡한 글을 잘못 바꾸는 비율

| 데이터 | 판단한 단어 | 잘못 바꾼 단어 | 단어당 | 문장당 |
|---|---|---|---|---|
| 영어 뉴스 | 1,846,843 | 96 | 0.0052% | 0.09% |
| 영어 위키백과 | 1,950,448 | 185 | 0.0095% | 0.17% |
| 한국어 웹 | 1,547,567 | 34 | 0.0022% | 0.03% |
| 한국어 뉴스 | 1,574,097 | 30 | 0.0019% | 0.03% |

잘못 바꾼 예 (괄호는 등장 횟수):

- 영어 글: `en`→두 (60), `di`→야 (47), `ch`→초 (16), `sp`→네 (6)
  → 대부분 프랑스어·이탈리아어 조각(*en route*, *di Maria*)이나 사전에 없는 이름. 일상 영어 단어는 거의 없다.
- 한국어 글: `했`→goT (8), `밋`→alt (5), `뜸`→Ema (5), `랙`→for (2)
  → 문장부호에 잘려 한 글자만 남은 조각들. 실제로 이 글자만 따로 치는 일은 드물다.

## 2. 잘못된 모드로 친 글을 고치는 비율

| 데이터 | 단어 | 고친 비율 | 문장이 통째로 고쳐진 비율: 맥락 모드 끔 → **켬** |
|---|---|---|---|
| 한국어 웹 → 영어 모드로 침 | 1,532,437 | 99.77% | 96.6% → **98.2%** |
| 한국어 뉴스 → 영어 모드로 침 | 1,567,410 | 99.71% | 95.7% → **97.6%** |
| 영어 뉴스 → 한글 모드로 침 | 1,846,843 | 91.32% | 24.4% → **68.3%** |
| 영어 위키백과 → 한글 모드로 침 | 1,950,435 | 92.25% | 27.0% → **69.6%** |

**혼자서는 못 고치고 남는 단어**

| 방향 | 가장 많이 남는 단어 | 이유 |
|---|---|---|
| 한국어를 영어 모드로 | `so`(내) 1,975 · `go`(해) 885 · `to`(새) 751 · `co`(채) · `al`(미) | 영어로도 흔한 단어라 일부러 안 바꿈 |
| 영어를 한글 모드로 | `새`(to) **106,098** · `무`(an) 15,182 · `내`(so) · `애`(do) · `재가`(work) · `양`(did) | 한국어로도 흔한 글자라 일부러 안 바꿈 |
| 영어를 한글 모드로 | `a`, `I` | 한 글자짜리는 혼자서는 판단하지 않음 |

영어 문장에는 `to`, `a`, `I`가 거의 매번 들어가서, 단어 하나씩만 보면 문장 4개 중 3개에 고쳐지지 않은 단어가 남는다.
**문장 맥락 모드**는 같은 문장 안에서 이미 고친 단어가 있으면, 같은 방향으로 이런 애매한 단어와 한 글자 단어도 바꾼다.
그 결과 영어 문장이 통째로 고쳐지는 비율이 24~27%에서 **68~70%**로 올랐다.
남는 경우는 주로 문장 첫 단어가 애매한 경우(`I want…`의 `I`는 앞에 고친 단어가 없어서 그대로)다.

## 3. 문장 맥락 모드의 부작용

맥락 모드는 "같은 문장에서 영어로 바뀐 단어 바로 뒤에 한국어를 섞어 쓰는" 경우에 한국어를 잘못 바꿀 수 있다
(`hello 내 친구`의 `내` → `so`). 한국어 시험 글 중 영어 단어가 섞인 문장 11,688개를 골라,
한국어는 한글 모드로 제대로 치고 영어 단어는 한글 모드로 잘못 쳐서 자동으로 고쳐졌다고 보고 측정했다.

| 데이터 | 문장 | 한국어 단어 | 잘못 바꾼 단어 비율: 끔 → 켬 | 잘못 바뀐 문장: 끔 → 켬 |
|---|---|---|---|---|
| 한국어 웹 | 6,987 | 114,709 | 0% → 0.014% | 0% → 0.23% |
| 한국어 뉴스 | 4,701 | 80,443 | 0.004% → 0.017% | 0.06% → 0.30% |

실제로 생긴 오류는 `새`→to (16), `는`→sms (4), `은`→dms (4), `내`→so (3) 뿐이다.
영어를 섞어 쓰는 문장 **약 400개에 1번** 이런 일이 생기는 셈이고, 대신 영어 문장 10개 중 4~5개가 추가로 통째로 고쳐진다.
그래서 기본으로 켜 두고, 설정 창의 "문장 맥락" 체크로 끌 수 있게 했다.
맥락은 `.` `?` `!`, Enter, 클릭, 창 전환, 그리고 **바꾸지 않고 남긴 단어**(`친구`처럼 분명한 한국어)가 나오면 끝난다.

## 4. 영어 단어 + 한국어 조사

한국어 시험 글에서 `SNS를`, `email을`처럼 **영어 단어 바로 뒤에 조사·어미가 붙은 단어** 6,819개(4,112종)를 골라,
통째로 한 모드로 쳤다고 보고 복원되는지 봤다. `LG전자`, `PGA투어`처럼 뒤가 조사가 아닌 합성어는 대상이 아니다.

| 친 모드 | 복원 비율 |
|---|---|
| 전부 영어 모드 (`SNSfmf`) | 92.9% |
| 전부 한글 모드 (`ㄴㅜㄴ를` 식으로 보임) | 92.7% |

못 고친 예: `kt는`, `tvN의`(소문자 약어), `trialkylamines의`, `Jagdtiger는`(사전에 없는 드문 단어).

이 기능을 처음 넣었을 때는 멀쩡한 한국어(`추가됩니다` → `cn가됩니다`, `남한은` → `ska한은`)를 잘라 버려서
**한국어 문장의 1.8%에서 잘못 바꾸는 문제**가 이 측정으로 드러났다. 한글 모드에서는 앞부분이 깨진 한글일 때만 자르도록 고쳐서 없앴다.

## 5. 두 언어 모두 말이 안 되는 입력

무작위 문자열 10만 개씩으로 시험했다.

| 입력 | 변환된 비율 | 설명 |
|---|---|---|
| 아이디처럼 영문+숫자 (`user123`) | **0%** | 숫자가 섞이면 판단하지 않음 |
| 비밀번호처럼 대소문자·숫자·기호 | **0%** | 같은 이유. 비밀번호 칸에서는 아예 기록도 안 함 |
| 무작위 소문자 3~10글자, 영어 모드 | 2.3% | 우연히 완전한 한글 음절이 되는 2.6% 중 대부분이 바뀜 |
| 무작위 키, 한글 모드 | 5.3% | 영어로 읽었을 때 사전에 있는 조각이면 바뀜 |
| 무작위 한글 음절 조합(`뷁꿇` 같은 것)을 영어 모드로 | 99.96% | 새로 생긴 말과 구별할 방법이 없어서 바꿈 |

정리하면 **숫자가 섞인 아이디·비밀번호는 안전하고, 순수 알파벳 무작위 입력은 2~5% 확률로 다른 무작위 문자로 바뀐다.**
처음 보는 한글 조합은 새 단어일 수도 있어서 바꾸는 쪽을 택했다.

## 6. Ctrl+Space 정확도

시험 문장을 통째로 잘못된 모드로 쳤다고 보고, Ctrl+Space로 원래 문장이 정확히(대문자까지) 돌아오는지 봤다.

| 데이터 | 문장 | 정확히 복원 |
|---|---|---|
| 영어 뉴스 (키보드로 칠 수 있는 문장) | 65,963 | 100% |
| 영어 위키백과 (〃) | 92,306 | 100% |
| 한국어 웹 | 100,000 | 83.1% (키로 다시 칠 수 있는 82,785문장 중 **100%**) |
| 한국어 뉴스 | 100,000 | 85.2% (〃 85,133문장 중 **100%**) |

한국어에서 나머지 15~17%는 원문 자체를 키 입력으로 똑같이 만들 수 없는 문장이다.
`좋네요ㅋ`처럼 완성 글자 바로 뒤에 자음이 붙은 경우는 같은 키를 다시 치면 IME가 `좋네욬`으로 합쳐 버리고,
`0.01%p`처럼 한국어 문장 속 영문자는 나머지와 함께 뒤집힌다. 변환 로직의 오류가 아니라 원문의 특성이다.

## 7. 기준값 비교

기준값을 하나씩 바꿔 가며 "잘못 바꾸는 비율"과 "고치는 비율"이 어떻게 움직이는지 봤다 (*는 현재 값).
이번 측정으로 두 값을 바꿨다: 깨진 한글일 때 필요한 영어 점수 2.0 → **1.5**, 영어가 한국어보다 높아야 하는 차이 2.0 → **3.0**.
그 결과 한국어 오변환은 절반으로 줄고(0.004% → 0.002%) 한글 모드로 친 영어를 고치는 비율은 0.4%p 올랐다.

**영어 모드 → 한글로 바꾸는 기준** (한국어 점수가 영어 점수보다 몇 이상 높아야 바꾸는지)

| 차이 | 영어 글을 잘못 바꿈 | 영어 모드로 친 한국어를 고침 |
|---|---|---|
| 0 | 0.128% | 99.89% |
| 0.5 | 0.012% | 99.80% |
| **1.0 \*** | **0.008%** | **99.74%** |
| 1.5 | 0.004% | 99.40% |
| 2.0 | 0.001% | 84.37% |

1.0이 꺾이는 지점이다. 더 낮추면 잘못 바꾸는 일이 15배까지 늘고, 2.0으로 올리면 고치는 비율이 15%p 떨어진다.

**한글 모드 → 영어로 바꾸는 기준**

| 설정 | 값 | 한국어 글을 잘못 바꿈 | 한글 모드로 친 영어를 고침 |
|---|---|---|---|
| 영어가 한국어보다 높아야 하는 차이 | 1.0 / 2.0 / **3.0\*** | 0.0067% / 0.0036% / **0.0017%** | 91.79% / 91.76% / **91.72%** |
| 이 이상 흔한 한국어는 안 바꿈 | 2.5 / **3.5\*** / 4.5 | 0.0013% / **0.0017%** / 0.0017% | 90.46% / **91.72%** / 91.72% |
| 깨진 한글일 때 필요한 영어 점수 | 1.0 / **1.5\*** / 2.0 / 3.0 | 0.0017% / **0.0017%** / 0.0017% / 0.0016% | 91.85% / **91.72%** / 91.28% / 89.14% |

(이 표의 "고침"은 맥락 모드 없이 단어 하나씩 판단한 값이다.)

## 8. 속도와 메모리

| 항목 | 값 |
|---|---|
| 단어 하나 판단 | 0.3~0.9µs (20만 번 평균, 측정마다 차이) |
| 단어 사전 불러오기 | 약 0.4초 (프로그램 시작 직후 백그라운드) |
| 단어 사전 메모리 | 약 70MB (영어 47.8만 + 한국어 48.7만 단어) |

판단 속도는 타이핑 속도와 비교하면 무시할 수준이다. 메모리는 줄일 여지가 있다 (아래 9번).

## 9. 한계와 남은 개선점

1. **문장 첫 단어가 애매하면 맥락이 시작되지 않는다**: `I want to go`를 한글 모드로 치면 `I`(ㅑ)는 그대로 남는다.
   이런 문장은 끝까지 친 뒤 Ctrl+Space로 한 번에 바꾸는 게 확실하다 (6번, 정확도 100%).
2. **메모리 70MB**: 단어 표를 정렬된 배열이나 압축 트라이로 바꾸면 정확도 변화 없이 10~20MB 수준으로 줄일 수 있다.
3. **영어+조사**: `kt는`, `tvN의` 같은 소문자 약어와 사전에 없는 드문 영어 단어는 복원하지 못한다.
4. **측정의 한계**: 실제 사용자 타이핑 기록이 아니라 문장을 잘못된 모드로 쳤다고 가정한 시뮬레이션이다.
   채팅체(카톡 등) 한국어는 웹 코퍼스에 일부만 들어 있다. 앱과 메모장에서의 실제 동작은 별도로 화면 테스트로 확인했다
   (`tools/smoke-test.ps1`).
