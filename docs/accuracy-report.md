# 자동 모드 정확도 분석 보고서

- 측정일: 2026-10-11 (v0.4.1)
- 대상: 자동 모드 판단 로직 (`AutoDetector`), 문장 맥락 모드, Ctrl+Space 변환 (`TypedSegment`)
- 원본 수치: [accuracy-results.json](accuracy-results.json) · 측정 코드: [tools/Evaluation](../tools/Evaluation/Program.cs)

## 요약

| 항목 | 한국어 글 | 영어 글 |
|---|---|---|

한 줄로: **멀쩡한 글을 잘못 건드리는 일은 매우 드물고, 한국어를 영어 모드로 친 경우는 거의 다 고쳐진다.
영어를 한글 모드로 친 경우는 `to`, `a`, `I` 같은 짧은 단어가 남지만 문장 맥락 모드로 문장 10개 중 7개는 통째로 고쳐진다.**

## 측정 방법

### 시험 데이터: 사전을 만들 때 쓰지 않은 글

사전을 만든 데이터로 시험하면 점수가 부풀려지므로, **사전에 전혀 쓰이지 않은** 라이프치히 대학 코퍼스(CC BY 4.0)
40만 문장으로 측정했다.

| 이름 | 내용 | 문장 | 단어 |
|---|---|---|---|
| 영어 뉴스 | eng_news_2024_100K | 100,000 | 200만 |
| 영어 위키백과 | eng_wikipedia_2016_100K | 100,000 | 209만 |
| 한국어 웹 | kor-kr_web_2015_100K (블로그·커뮤니티 등) | 100,000 | 172만 |
| 한국어 뉴스 | kor_newscrawl_2016_100K | 100,000 | 181만 |

사전은 자막·위키백과(2021–2023)·뉴스(2022)·ENABLE·Hunspell로 만들었으므로 출처와 연도가 겹치지 않는다
([DICTIONARIES.md](../tools/DICTIONARIES.md)).

### 실제 타이핑 흉내

- 문장을 앱과 똑같이 스페이스·`. , ? ! ; :`에서 끊어 단어로 나눴다.
- **제대로 친 경우**: 영어는 영어 모드로, 한글은 한글 모드로 쳤다고 보고, 하나라도 바뀌면 "잘못 바꿈"으로 셌다.
- **잘못된 모드로 친 경우**: 영어를 한글 모드로(`hello` → `ㅗ디ㅣㅐ`), 한글을 영어 모드로(`안녕` → `dkssud`) 쳤다고 보고,
  정확히 원래대로 돌아오면 "고침"으로 셌다. 대문자는 Shift를 눌렀다고 보고 그대로 유지돼야 성공.

## 1. 멀쩡한 글을 잘못 바꾸는 비율

| 데이터 | 판단한 단어 | 잘못 바꾼 단어 | 단어당 | 문장당 |
|---|---|---|---|---|
| 영어 뉴스 | 1,846,843 | 123 | 0.0067% | 0.12% |
| 영어 위키백과 | 1,950,448 | 224 | 0.0115% | 0.21% |
| 한국어 웹 | 1,547,567 | 36 | 0.0023% | 0.04% |
| 한국어 뉴스 | 1,574,097 | 35 | 0.0022% | 0.04% |

잘못 바꾼 예: 영어 글은 `en`→두 (60), `di`→야 (47), `ch`→초 (16) 같은 외국어 조각과 사전에 없는 이름,
한국어 글은 `했`→goT (8), `밋`→alt (5) 같이 문장부호에 잘려 한 글자만 남은 조각. 일상 단어는 거의 없다.
v0.4.0보다 영어 글에서 조금 늘었는데(105→123, 195→224), 숫자·영문 한 글자 뒤의 한글을 고치게 하면서
`Drua`→`D겸` 같은 드문 이름 조각이 생긴 것이다. 대신 숫자 + 한글 복원이 91%→99.4%로 올랐다.

## 2. 잘못된 모드로 친 글을 고치는 비율

| 데이터 | 단어 | 고친 비율 | 문장이 통째로 고쳐진 비율: 맥락 모드 끔 → **켬** |
|---|---|---|---|
| 한국어 웹 → 영어 모드로 침 | 1,532,437 | 99.77% | 96.6% → **98.2%** |
| 한국어 뉴스 → 영어 모드로 침 | 1,567,410 | 99.71% | 95.7% → **97.6%** |
| 영어 뉴스 → 한글 모드로 침 | 1,846,843 | 91.32% | 24.4% → **68.3%** |
| 영어 위키백과 → 한글 모드로 침 | 1,950,435 | 92.25% | 27.0% → **69.6%** |

혼자서는 못 고치고 남는 단어는 두 언어 모두 말이 되는 것들이다: 영어 모드에서 `so`(내), `go`(해), `to`(새),
한글 모드에서 `새`(to) 106,098번, `무`(an), `내`(so), 그리고 한 글자짜리 `a`, `I`.
**문장 맥락 모드**는 같은 문장에서 이미 고친 단어가 있으면 같은 방향으로 이런 단어도 바꿔서 통째로 고쳐지는 비율을 크게 올린다.

## 3. 문장 맥락 모드의 부작용

영어 단어 뒤에 한국어를 섞어 쓰면(`hello 내 친구`) `내`가 `so`로 바뀔 수 있다. 영어가 섞인 한국어 문장 11,688개로 측정했다.

| 데이터 | 한국어 단어 | 잘못 바꾼 단어 비율: 끔 → 켬 | 잘못 바뀐 문장: 끔 → 켬 |
|---|---|---|---|
| 한국어 웹 | 114,709 | 0% → 0.014% | 0% → 0.23% |
| 한국어 뉴스 | 80,443 | 0.004% → 0.017% | 0.06% → 0.30% |

실제 오류는 `새`→to (16), `는`→sms (4), `은`→dms (4), `내`→so (3)뿐이다. 영어를 섞어 쓰는 문장 약 400개에 1번이고,
대신 영어 문장 10개 중 4–5개가 추가로 통째로 고쳐지므로 기본으로 켜 두고 설정에서 끌 수 있게 했다.

반대 방향도 쟀다. 영어 모드로 친 한국어가 고쳐져 맥락이 생긴 뒤에는 `분석부터 go`의 `go`를 `해`로 바꾼다.
이때 일부러 영어로 쓴 단어가 바뀌는 비율은 영어가 섞인 한국어 문장의 영어 단어 21,817개 중 0.07%→0.09%로 늘었다
(`so`→내, `dis`→얀 등 3건).

## 4. 영어와 한글이 섞인 단어

| 종류 | 예 | 실제 등장 수 | 영어 모드로 쳤을 때 | 한글 모드로 쳤을 때 |
|---|---|---|---|---|
| 영어 + 조사 | `SNS를`, `email을`, `giffen은`, `ch4가`, `rebate가` | 7,202 | 98.4% | 93.2% |
| 영어·숫자 + 한글 전체 (합성어 포함) | 위 + `LG전자`, `engel곡선`, `A씨는`, `B형`, `FA컵` | 11,908 | 80.2% | 76.9% |

한글 모드에서는 숫자가 섞인 영어(`ch4`)를 일부러 판단하지 않는다(`초4가`가 실제 한국어일 수 있어서).
못 고치는 예: `SK텔레콤은`처럼 약어 뒤 긴 회사명, `A조`(`wh`가 영어 약어로도 흔함), 사전에 없는 드문 이름.
소문자 한 글자는 긴 조사나 흔한 낱말 앞에서만 쪼갠다(`a는`, `e스포츠`). `a가`처럼 짧으면 너무 애매하다.

## 5. 숫자 + 한글

한국어 시험 글의 `3개`, `1분기`, `65세`, `2024년에`처럼 숫자 바로 뒤에 한글이 붙은 단어 120,650개를 영어 모드로 쳤다고 보고 측정했다.

| 항목 | 결과 |
|---|---|
| 복원 비율 | **99.4%** |
| 영어 글의 `3rd`, `20th`, `1980s`, `10kg` 7,690개를 잘못 바꾼 수 | **0** |

단위·조사뿐 아니라 숫자 뒤의 일반 낱말(`1차전에서`, `6자회담`, `+2만큼`)도 완전한 한글이면 고친다.
남는 것: `1군`, `3루`처럼 뒤의 한 글자가 영어 조각(`rns`, `fn`)으로도 읽히는 경우.

## 6. 따옴표·괄호·하이픈 등이 붙은 단어

| 종류 | 예 | 복원 비율 | 제대로 쳤을 때 잘못 바꿈 |
|---|---|---|---|
| 한국어 | `“이번`, `것”이라고`, `시·군`, `달러(약`, `제2차`, `5%로`, `양해각서(MOU)를` | 98.6% | 0% |
| 영어 | `price-consumption`, `it’s`, `(or`, `I'm` | 87.9% | 0.008% |

단어 안의 문자 중 글자가 아닌 것(따옴표, 괄호, 가운뎃점, 숫자 등)은 두 모드에서 같은 키이므로 그대로 두고,
나머지 부분을 따로 판단한다. 대문자 약어(`MOU`, `SDS`)나 제대로 친 영어(`www`)는 그대로 둔다.

## 7. 앱이 못 고치는 것 찾기 (실패 분석)

40만 문장의 **모든 단어**를 잘못된 모드로 쳤다고 보고, 복원에 실패한 것을 모양별로 묶었다.
이 분석으로 따옴표·괄호·숫자가 붙은 단어가 한국어 단어의 약 4%를 차지하면서 전부 실패하고 있다는 걸 발견해 6번으로 고쳤다.
지금 남은 주요 실패:

| 한국어를 영어 모드로 | 예 | 전체 단어 중 |
|---|---|---|
| 한국어로도 영어로도 말이 되는 한 글자 | `내`, `해`, `새` | 0.24% |
| 영문 + 한글 합성어 | `A매치`, `SK텔레콤은`, `A조` | 0.06% |
| 괄호 안 영어 | `중동호흡기증후군(MERS`, `양해각서(MOU)를` | 0.06% |

| 영어를 한글 모드로 | 예 | 전체 단어 중 |
|---|---|---|
| 짧은 단어 | `to`, `a`, `I`, `an` (맥락 모드가 일부 해결) | 7.85% |
| 숫자 + 영어 | `20th`, `1980s` (`20소`가 한국어일 수 있어 일부러 둠) | 0.15% |
| 애매한 부분이 있는 하이픈 단어 | `so-called`, `co-founder` | 0.10% |

이 과정에서 생긴 오변환도 측정으로 잡아 되돌렸다:
`British`→`B갸샤노`(첫 대문자를 약어로 봄), `Upwork`→`Up재가`, `추가됩니다`→`cn가됩니다`,
아이디 `rlaalswn12`→`김민주12`(숫자 뒤 아이디), 비밀번호형 문자열, `BioLargo`→`BioLar해`, `7Bravo`→`7Bra패`,
`CEO들의`→`CEOemf의`, `quantity가`→`벼무샤쇼가`(사전에 없는 한글로 통째로 읽음).

## 8. 두 언어 모두 말이 안 되는 입력

무작위 문자열 10만 개씩.

| 입력 | 변환된 비율 | 설명 |
|---|---|---|
| 아이디처럼 영문+숫자 (`user123`) | **0%** | 영문 뒤에 숫자로 끝나면 판단하지 않음 |
| 비밀번호처럼 대소문자·숫자·기호 | **0.6%** | 비밀번호 칸에서는 아예 기록하지 않음 |
| 무작위 소문자, 영어 모드 | 2.7% | 우연히 완전한 한글 음절이 되는 경우 |
| 무작위 키, 한글 모드 | 5.8% | 영어로 읽었을 때 사전에 있는 조각이면 바뀜 |
| 무작위 한글 음절 조합을 영어 모드로 | 99.96% | 새 단어와 구별할 수 없어서 바꿈 |

추가로, 로그인 화면처럼 **칸에 단어 하나만 치고 Enter**를 누르면 바뀔 결과가 흔한 말(`다음`, `네`, `감사합니다`)일 때만 바꾼다.
채팅에서 한 단어로 보내는 말은 바꾸고, 이름으로 만든 아이디(`rlaalswn`→`김민주`)는 그대로 둔다.

## 11. 속도와 메모리

| 항목 | 값 |
|---|---|
| 단어 하나 판단 | 0.3–1.0µs |
| 단어 사전 불러오기 | 약 0.2초 (프로그램 시작 직후 백그라운드) |
| 단어 사전 메모리 | 16MB (영어 47.8만 + 한국어 48.7만 단어). 처음 70MB에서 저장 방식만 바꿔 줄였고, 모든 측정 결과가 바꾸기 전과 똑같았다 |
| 프로그램 전체 메모리 (private) | 약 69MB (v0.3.0은 127MB) |

## 12. 한계

1. 문장 첫 단어가 애매하면 맥락이 시작되지 않는다(`I want to go`의 `I`). 이런 문장은 Ctrl+Space가 확실하다.
2. 영문 + 긴 합성어(`SK텔레콤은`), 괄호 속 영어(`(MERS`), 한 글자로 두 언어 모두 말이 되는 `내`·`해`·`새`는 아직 못 고친다.
3. 실제 사용자 타이핑 기록이 아니라 시뮬레이션이다. 채팅체 한국어는 웹 코퍼스에 일부만 들어 있다.
   앱과 메모장에서의 실제 동작은 화면 테스트로 따로 확인한다 (`tools/smoke-test.ps1`).
