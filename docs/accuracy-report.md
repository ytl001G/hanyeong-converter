## 측정 방법

### 시험 데이터: 사전을 만들 때 쓰지 않은 글

사전을 만든 데이터로 시험하면 점수가 부풀려지므로, **사전에 전혀 쓰이지 않은** 라이프치히 대학 코퍼스(CC BY 4.0)로 측정했다.

| 이름 | 내용 | 문장 | 쓰임 |
|---|---|---|---|
| 영어 뉴스 | eng_news_2024_100K | 100,000 | 기본 시험 (1–5, 7–11장) |
| 영어 위키백과 | eng_wikipedia_2016_100K | 100,000 | 〃 |
| 한국어 웹 | kor-kr_web_2015_100K (블로그·커뮤니티 등) | 100,000 | 〃 |
| 한국어 뉴스 | kor_newscrawl_2016_100K | 100,000 | 〃 |
| 한국어 웹·뉴스 (큰 표본) | kor-kr_web_2015_1M, kor_newscrawl_2016_1M, kor_news_2020_1M | 299만 | 예외 케이스 (6장) |
| 영어 뉴스·웹 | eng_news_2023_300K, eng-uk_web_2002_300K, eng_newscrawl-public_2018_100K | 70만 | 〃 |

큰 표본에서는 기본 시험과 겹치는 문장을 뺐다. 사전은 자막·위키백과(2021–2023)·뉴스(2022)·ENABLE·Hunspell,
이름 목록은 Wikidata·미국 인구조사·GeoNames로 만들었으므로 시험 글과 출처가 겹치지 않는다 ([DICTIONARIES.md](../tools/DICTIONARIES.md)).

### 실제 타이핑 흉내

- 문장을 앱과 똑같이 스페이스·`. , ? ! ; :`에서 끊어 단어로 나눴다.
- **제대로 친 경우**: 영어는 영어 모드로, 한글은 한글 모드로 쳤다고 보고, 하나라도 바뀌면 "잘못 바꿈"으로 셌다.
- **잘못된 모드로 친 경우**: 영어를 한글 모드로(`hello` → `ㅗ디ㅣㅐ`), 한글을 영어 모드로(`안녕` → `dkssud`) 쳤다고 보고,
  정확히 원래대로 돌아오면 "고침"으로 셌다. 대문자는 Shift를 눌렀다고 보고 그대로 유지돼야 성공.
- 판단은 앱과 같은 함수(`AutoDetector.Suggest`)로 했다.

### 앱 전체 동작 확인

시험 글 측정과 별도로, 키보드 훅·입력창·한글 IME를 흉내 낸 **화면 없는 앱 테스트**로 앱 전체를 확인한다.

- `tests/HanYeong.Tests`: 문장 맥락, 앞 단어 고치기, Enter·방향키, 터미널 입력, 한자 키 등
- `reported-cases.tsv`: 사용자가 알려 준 사례를 모아 둔 목록

또 **자동 테스터**(`tools/Fuzz`)가 사전·이름 목록으로 한국어·영어 문장을 만들어, 두 모드로 쳐 보며 실패를 찾는다.
문장에는 영어 + 조사, 숫자 + 단위, 약어, 이름, 괄호를 섞는다. 지금은 원래 구별할 수 없는 경우를 빼면
약 400문장에 1번 실패가 나온다. 실제 IME·앱에서만 보이는 동작은 화면 테스트(`tools/smoke-test.ps1`)로 확인한다.

## 1. 멀쩡한 글을 잘못 바꾸는 비율

| 데이터 | 판단한 단어 | 단어 하나씩 판단 | 앱 동작 (같은 문장 앞 단어 반영) |
|---|---|---|---|
| 영어 뉴스 | 1,846,843 | 100개, 0.0054% | **0.0039%** |
| 영어 위키백과 | 1,950,448 | 207개, 0.0106% | **0.0059%** |
| 한국어 웹 | 1,547,567 | 36개, 0.0023% | **0.0012%** |
| 한국어 뉴스 | 1,574,097 | 37개, 0.0024% | **0.0014%** |

앱은 같은 문장에서 앞 단어를 확실한 영어(또는 한국어)로 그대로 두었으면, 지금 그 모드로 쓰는 중이라고 본다.
그래서 뒤에 오는 3글자 이하 단어는 반대 언어가 훨씬 그럴듯할 때만 바꾼다.

단어 하나씩 판단할 때 잘못 바꾸는 것은 대부분 짧은 조각이다.
- 영어 글: `en`→두, `di`→야, `ch`→초 같은 외국어 조각
- 한국어 글: `했`→goT, `밋`→alt처럼 문장부호에 잘려 한 글자만 남은 조각

앱 동작에서는 이런 조각이 대부분 앞 단어 덕분에 그대로 남는다. 남는 것은 문장 첫머리의 조각과 사전에 없는 이름(`Emefiele`) 정도다.

## 2. 잘못된 모드로 친 글을 고치는 비율

| 데이터 | 단어 | 고친 비율 | 문장이 통째로 고쳐진 비율: 맥락 끔 → **켬** |
|---|---|---|---|
| 한국어 웹 → 영어 모드로 침 | 1,532,437 | 99.76% | 96.6% → **98.8%** |
| 한국어 뉴스 → 영어 모드로 침 | 1,567,410 | 99.70% | 95.6% → **98.2%** |
| 영어 뉴스 → 한글 모드로 침 | 1,846,843 | 93.20% | 32.1% → **90.0%** |
| 영어 위키백과 → 한글 모드로 침 | 1,950,435 | 93.78% | 33.8% → **87.7%** |

혼자서는 못 고치는 단어는 두 언어 모두 말이 되는 것들이다. 예를 들면 영어 모드의 `so`(내)·`go`(해)·`to`(새),
한글 모드의 `새`(to)·`무`(an), 한 글자짜리 `a`가 있다. 이런 단어는 혼자 있으면 지금 모드 그대로 둔다.
같은 문장에 이미 고친 단어가 있으면 **문장 맥락**으로 같은 방향으로 바꾸고,
뒤 단어가 고쳐질 때는 **바로 앞 단어도 거슬러** 고친다. 거슬러 고치는 예:

- `ㅑ ㅈ무ㅅ` → `I want`
- `무 메ㅔㅣㄷ` → `an apple` (`내`처럼 양쪽이 비슷하게 흔하면 그대로)
- `so wlq` → `내 집`
- `20소 ㅇㄱㄷ므` → `20th dream`

한글 모드에서 Shift로 친 영어 대문자(`SEC`, `I`, `Anaut`)는 영어로 본다. Shift는 이 키들의 한글을 바꾸지 않기 때문이다.

## 3. 문장 맥락의 부작용

영어 단어 뒤에 한국어를 섞어 쓰면 맥락 때문에 한국어가 바뀔 수 있다. 예를 들어 `hello 내 친구`에서 `내`가 `so`가 될 수 있다.
앱은 이렇게 맥락 때문에만 바뀐 단어 바로 뒤에 확실한 한국어 단어(`친구`)가 오면, 앞 단어를 원래대로(`내`) 되돌린다.
반대로 뒤가 영어(`hello so good`)면 그대로 둔다. 영어가 섞인 한국어 문장 11,688개로 측정했다.

| 데이터 | 한국어 단어 | 잘못 바꾼 단어 비율: 맥락 끔 → 켬 | 잘못 바뀐 문장: 맥락 끔 → 켬 |
|---|---|---|---|
| 한국어 웹 | 114,709 | 0% → 0.006% | 0% → 0.10% |
| 한국어 뉴스 | 80,443 | 0.004% → 0.007% | 0.06% → 0.13% |

남는 오류는 `는`→sms, `새`→to처럼 바로 뒤에 확실한 한국어가 없는 경우(문장 끝 등)이고, 영어를 섞어 쓰는 문장 약 900개에 1번이다.
반대로 영어 모드로 친 한국어가 고쳐진 뒤 일부러 영어로 쓴 단어가 바뀌는 비율은
영어 단어 21,817개 중 0.06% → 0.08%(`so`→내, `dis`→얀 등)다. 영어 문장의 절반 이상이 추가로 통째로 고쳐지므로
문장 맥락은 기본으로 켜 두고 설정에서 끌 수 있게 했다.

## 4. 영어와 한글이 섞인 단어

| 종류 | 예 | 실제 등장 수 | 영어 모드로 쳤을 때 | 한글 모드로 쳤을 때 |
|---|---|---|---|---|
| 영어 + 조사 | `SNS를`, `email을`, `giffen은`, `ch4가`, `rebate가` | 7,204 | 98.3% | 94.1% |
| 영어·숫자 + 한글 전체 (합성어 포함) | 위 + `LG전자`, `SK텔레콤은`, `A씨는`, `B형`, `A매치` | 11,908 | 91.4% | 88.7% |

판단 기준은 이렇다. 아래 규칙은 영어 모드와 한글 모드에 똑같이 쓴다. 다만 한글 모드에서 완전한 글자로 친 것은
한국어를 일부러 친 것일 가능성이 높아서, 영어로 보려면 5글자 이상의 흔한 영어여야 한다.

- **영어 + 조사인지, 한국어 한 낱말인지**: 두 쪽을 함께 본다. 앞부분이 영어 단어인지, 같은 부분을 한글로 읽으면 한국어 낱말인지 따진다.
  - `gyrus에`, `gyri는`은 영어 + 조사로 본다 (`효견`은 한국어 낱말이 아님).
  - `해소시켜`, `처리됩니다`는 한국어로 둔다 (`해소`·`처리`가 낱말).
  - 영어가 훨씬 흔하면 영어 쪽을 택한다 (`work하려고`).
- **사전에 없는 영어**: 앞부분이 이름 목록에 있으면 그 이름에서 쪼갠다 (`Dobbek에게서`이지 `Dobb다에게서`가 아님, `Dorda도`).
  이름 목록에도 없으면, 쪼갤 수 있는 자리 중 뒷부분이 한국어 어미로 더 흔한 쪽을 택한다.
  - 한글 모드에서는 화면에 낱자모가 절반 이상일 때만 영어로 본다 (`ㅎㄱ메ㅗㅛ인건가`→`graphy인건가`).
    `신ㄱ노는`처럼 자모 하나가 낀 한국어는 오타로 보고 그대로 둔다.
- **드문 긴 영어**: 6글자 이상이고 한글로 읽으면 말이 안 되면, `이`·`에`·`도`·`로` 앞에서 영어로 본다.
  사전에 드물게 있는 단어(`microphonic이`)와, 사전에 없어도 영어처럼 생긴 단어(`vental도`)가 해당한다.
  영어처럼 생겼는지는 세 글자 조각(`ven`, `ent`, `nta`, `tal`)이 모두 사전 단어 20개 이상에 나오는지로 본다.
  무작위 6–10글자 문자열은 3.6%만 이 조건을 통과한다.
- **조사·어미 목록**: 한국어 사전에서 명사 뒤에 붙는 어미를 빈도순으로 모아 채웠다
  (`이잖아`, `이거든요`, `때문에`, `해줘`, `됐어요`, `라는거지`, `이구나`, `인건가` 등).
  영어 단어 끝과 키가 자주 겹치는 것(`좀`=wha, `째`=Wo)은 뺐다.
- **자음 하나 + 한국어**: `ㄱ씨는`, `ㅅ아파트`는 기사에서 익명을 쓰는 방식이라 한글 모드에서 그대로 두고,
  영어 모드로 친 경우(`rTlsms`)는 이렇게 고친다.
- **실수로 이어진 Shift**: 쌍자음 키를 치고 Shift가 다음 키까지 이어진 경우만 고친다.
  Shift를 누를 이유가 없는 단어(`dkssUD`)는 그대로 둔다.
  - 글자 중간에서 Shift를 뗀 경우는 단어 맨 앞이어도 고친다 (`TMs거야`→`쓴거야`, `s`는 `쓴`의 받침).
  - 글자 경계에서 뗀 경우는 약어 + 조사일 수 있어서(`RK는`, `SK는`), 맨 앞이 아니고 결과가 4글자 이상일 때만 고친다
    (`qlrygkslRK`→`비교하니까`).

못 고치는 예: `K리그1`(끝에 숫자), `n번방`, 드문 영어 + `고`·`다`·`가` 같은 키 2개 조사(`Gabin지`). 마지막 경우는 이름 끝과 구별이 안 돼서 일부러 둔다.

## 5. 숫자 + 한글

한국어 시험 글의 `3개`, `1분기`, `65세`, `2024년에`처럼 숫자 바로 뒤에 한글이 붙은 단어 120,650개를 영어 모드로 쳤다고 보고 측정했다.

| 항목 | 결과 |
|---|---|
| 복원 비율 | **99.8%** |
| 영어 글의 `3rd`, `20th`, `1980s`, `10kg` 7,690개를 잘못 바꾼 수 | **0** |

다음 경우는 고친다.
- 숫자 뒤가 단위·조사인 경우 (`3개`, `6보다`)
- 두 글자 이상의 한글 (`1차전에서`)
- 한국어로 흔하고 영어로 흔하지 않은 한 글자 (`1심`, `3루`)

다음 경우는 영어로 둔다.
- 숫자 뒤 영어가 우연히 완전한 한글이 되는 경우 (`th`→소, `cm`→츠). 목록 `Data/number-suffixes-en.txt`로 관리한다.
- 숫자 앞 영문 (`ch4`=챕터 4, `mp3`). 코드로 본다.

단, 숫자 앞에 오는 한국어(`제2차`, `고3`)는 고친다. 목록 `Data/number-prefixes.txt`로 관리한다.
한글 모드에서 숫자 뒤 자모 하나(`75ㄴ`)는 영어(`75s`)로 본다.

| 사전에 없는 이름 (문장 중간 대문자) | `Emefiele`, `Ndidi` | 105,343 | 0.27% | 90.4% |
| CamelCase·소문자 시작 약어 | `CyberArk`, `iOS`, `FedEx` | 17,346 | 0.08% | 76.8% |
| 숫자 + 영어 | `3rd`, `10kg`, `4chan` | 26,654 | 0.08% | |

남은 예:
- 사전에 없는 이름 중 `E`·`R`로 시작하는 것 (`Emefiele`). `E`=ㄸ, `R`=ㄲ이라 한국어처럼 읽힌다.
- 한글 모드로 친 대문자 한 글자 `E`, `P`. `ㄸ`, `ㅖ`와 키가 같아 구별할 수 없다.
- 자모 하나 + 흔한 낱말 (`ㄷ업체는`→`e업체는`, `ㅇㅇㅇ의`→`ddd의`). `e스포츠`처럼 영문 한 글자 + 낱말과 키가 같다.

## 7. 앱이 못 고치는 것 찾기 (실패 분석)

기본 시험 40만 문장의 **모든 단어**를 잘못된 모드로 쳤다고 보고, 단어 하나씩 판단했을 때 실패한 것을 모양별로 묶었다.

| 한국어를 영어 모드로 | 예 | 전체 단어 중 |
|---|---|---|
| 한국어로도 영어로도 말이 되는 한 글자 | `내`, `해`, `새` (문장 맥락이 일부 해결) | 0.24% |
| 영문 + 한글 합성어 | `t당`, `A형`, `A군은` | 0.03% |
| 한글 + 숫자 | `제2`, `고3` | 0.02% |

| 영어를 한글 모드로 | 예 | 전체 단어 중 |
|---|---|---|
| 짧은 단어 | `to`, `a`, `an`, `so` (문장 맥락이 대부분 해결) | 6.2% |
| 애매한 부분이 있는 하이픈 단어 | `so-called`, `co-founder` | 0.09% |
| 숫자 + 영어 | `20th`, `4th` (혼자면 `20소`가 한국어일 수 있어 둠, 다음 단어가 영어면 고침) | 0.09% |

## 8. 두 언어 모두 말이 안 되는 입력

무작위 문자열 10만 개씩.

| 입력 | 변환된 비율 | 설명 |
|---|---|---|
| 아이디처럼 영문+숫자 (`user123`) | **0%** | 영문 뒤에 숫자로 끝나면 판단하지 않음 |
| 비밀번호처럼 대소문자·숫자·기호 | **0.7%** | 비밀번호 칸에서는 아예 기록하지 않음 |
| 무작위 소문자, 영어 모드 | 2.8% | 우연히 완전한 한글 음절이 되는 경우 |
| 무작위 키, 한글 모드 | 5.8% | 영어로 읽었을 때 사전에 있는 조각이면 바뀜 |
| 무작위 한글 음절 조합을 영어 모드로 | 99.95% | 새 단어와 구별할 수 없어서 바꿈 |

**칸에 단어 하나만 치고 Enter**를 누르는 경우도 다른 단어처럼 바꾼다. 설정의 "로그인 칸 아이디 보호"를 켜면,
바뀔 결과가 사람 이름처럼 보일 때(성씨로 시작하는 2–4글자, 예: `rlaalswn`→`김민주`) 아이디로 보고 그대로 둔다.

## 9. Ctrl+Space 정확도

| 데이터 | 문장 | 정확히 복원 |
|---|---|---|
| 영어 뉴스 / 위키백과 (키보드로 칠 수 있는 문장) | 65,963 / 92,306 | 100% |
| 한국어 웹 / 뉴스 | 100,000 / 100,000 | 83.1% / 85.2% (키로 다시 칠 수 있는 문장 중 **100%**) |

한국어의 나머지는 원문 자체를 키로 재현할 수 없는 문장이다.
예를 들어 `좋네요ㅋ`는 같은 키를 치면 IME가 `좋네욬`으로 합친다.

## 12. 한계

1. 두 언어 모두 말이 되는 한 글자(`내`·`해`·`새`)는 문장에 혼자 있으면 지금 모드 그대로 둔다. 이런 문장은 Ctrl+Space가 확실하다.
2. 키만으로는 구별할 수 없는 경우가 있다.
   - `ㄸ`·`ㄲ`·`ㅃ`·`ㅆ`·`ㅉ` 키(E·R·Q·T·W)로 시작하는 사전에 없는 이름
   - 웃음 `ㅎㅎ`와 `gg`
   - 드문 영어 + 키 2개 조사 (`Gabin지`)
3. 실제 사용자 타이핑 기록이 아니라 시뮬레이션이다. 채팅체 한국어는 웹 코퍼스에 일부만 들어 있다.
   사용자가 알려 준 사례는 `reported-cases.tsv`에 모아 앱 전체 동작으로 매번 확인한다.
