## 측정 방법

### 시험 데이터: 사전을 만들 때 쓰지 않은 글

사전을 만든 데이터로 시험하면 점수가 부풀려지므로, **사전에 전혀 쓰이지 않은** 라이프치히 대학 코퍼스(CC BY 4.0)로 측정했다.

| 이름 | 내용 | 문장 | 쓰임 |
|---|---|---|---|
| 영어 뉴스 | eng_news_2024_100K | 100,000 | 기본 시험 (1–3, 7–11장) |
| 영어 위키백과 | eng_wikipedia_2016_100K | 100,000 | 〃 |
| 한국어 웹 | kor-kr_web_2015_100K (블로그·커뮤니티 등) | 100,000 | 〃 |
| 한국어 뉴스 | kor_newscrawl_2016_100K | 100,000 | 〃 |
| 한국어 웹·뉴스 (큰 표본) | kor-kr_web_2015_1M, kor_newscrawl_2016_1M, kor_news_2020_1M | 299만 | 예외 케이스 (6장) |
| 영어 뉴스·웹 | eng_news_2023_300K, eng-uk_web_2002_300K, eng_newscrawl-public_2018_100K | 70만 | 〃 |

예외 케이스용 큰 표본에서는 기본 시험과 겹치는 문장(약 1만)을 뺐다.
사전은 자막·위키백과(2021–2023)·뉴스(2022)·ENABLE·Hunspell, 이름 목록은 Wikidata·미국 인구조사·GeoNames로 만들었으므로
시험 글과 출처가 겹치지 않는다 ([DICTIONARIES.md](../tools/DICTIONARIES.md)).

### 실제 타이핑 흉내

- 문장을 앱과 똑같이 스페이스·`. , ? ! ; :`에서 끊어 단어로 나눴다.
- **제대로 친 경우**: 영어는 영어 모드로, 한글은 한글 모드로 쳤다고 보고, 하나라도 바뀌면 "잘못 바꿈"으로 셌다.
- **잘못된 모드로 친 경우**: 영어를 한글 모드로(`hello` → `ㅗ디ㅣㅐ`), 한글을 영어 모드로(`안녕` → `dkssud`) 쳤다고 보고,
  정확히 원래대로 돌아오면 "고침"으로 셌다. 대문자는 Shift를 눌렀다고 보고 그대로 유지돼야 성공.
- 판단은 앱과 같은 함수(`AutoDetector.Suggest`)로 했다. 키보드 훅·입력창·IME까지 포함한 앱 전체 동작은 화면 없는 테스트
  (`tests/HanYeong.Tests`, 사용자 신고 사례는 `reported-cases.tsv`)와 실제 화면 테스트(`tools/smoke-test.ps1`)로 따로 확인한다.

## 1. 멀쩡한 글을 잘못 바꾸는 비율

| 데이터 | 판단한 단어 | 잘못 바꾼 단어 | 단어당 | 문장당 |
|---|---|---|---|---|
| 영어 뉴스 | 1,846,843 | 95 | 0.0051% | 0.09% |
| 영어 위키백과 | 1,950,448 | 207 | 0.0106% | 0.19% |
| 한국어 웹 | 1,547,567 | 35 | 0.0023% | 0.03% |
| 한국어 뉴스 | 1,574,097 | 37 | 0.0024% | 0.04% |

잘못 바꾼 예: 영어 글은 `en`→두 (60), `di`→야 (47), `ch`→초 (16) 같은 외국어 조각과 사전에 없는 이름,
한국어 글은 `했`→goT (8), `밋`→alt (5) 같이 문장부호에 잘려 한 글자만 남은 조각. 일상 단어는 거의 없다.
v0.4.1보다 영어 글에서 줄었는데(123→95, 224→207), 이름 목록(66만 개)으로 `Ndidi`, `Kowalczyk` 같은 이름을 영어로 두게 했기 때문이다.

## 2. 잘못된 모드로 친 글을 고치는 비율

| 데이터 | 단어 | 고친 비율 | 문장이 통째로 고쳐진 비율: 맥락 모드 끔 → **켬** |
|---|---|---|---|
| 한국어 웹 → 영어 모드로 침 | 1,532,437 | 99.76% | 96.5% → **98.7%** |
| 한국어 뉴스 → 영어 모드로 침 | 1,567,410 | 99.69% | 95.5% → **98.1%** |
| 영어 뉴스 → 한글 모드로 침 | 1,846,843 | 92.32% | 28.2% → **76.8%** |
| 영어 위키백과 → 한글 모드로 침 | 1,950,435 | 92.98% | 29.9% → **76.0%** |

혼자서는 못 고치고 남는 단어는 두 언어 모두 말이 되는 것들이다: 영어 모드에서 `so`(내), `go`(해), `to`(새),
한글 모드에서 `새`(to) 106,053번, `무`(an), `내`(so), 그리고 한 글자짜리 `a`.
**문장 맥락 모드**는 같은 문장에서 이미 고친 단어가 있으면 같은 방향으로 이런 단어도 바꾼다.
v0.5.0부터는 뒤 단어가 고쳐질 때 **바로 앞 단어도 거슬러** 고친다: 깨진 자모(`ㅑ ㅈ무ㅅ` → `I want`)와,
영어 쪽이 훨씬 흔한 짧은 단어(`무 메ㅔㅣㄷ` → `an apple`; `내`처럼 양쪽이 비슷하면 그대로).
한글 모드에서 Shift로 친 대문자(`SEC`, `I`)도 영어로 본다. 이 둘로 영어 문장이 통째로 고쳐지는 비율이 68–70%에서 76–77%로 올랐다.

## 3. 문장 맥락 모드의 부작용

영어 단어 뒤에 한국어를 섞어 쓰면(`hello 내 친구`) `내`가 `so`로 바뀔 수 있다. 영어가 섞인 한국어 문장 11,688개로 측정했다.

| 데이터 | 한국어 단어 | 잘못 바꾼 단어 비율: 끔 → 켬 | 잘못 바뀐 문장: 끔 → 켬 |
|---|---|---|---|
| 한국어 웹 | 114,709 | 0% → 0.017% | 0% → 0.27% |
| 한국어 뉴스 | 80,443 | 0.004% → 0.021% | 0.06% → 0.36% |

실제 오류는 `새`→to (18), `는`→sms (6), `은`→dms (5), `내`→so (4)뿐이다. 영어를 섞어 쓰는 문장 약 300개에 1번이고,
대신 영어 문장 2개 중 1개가 추가로 통째로 고쳐지므로 기본으로 켜 두고 설정에서 끌 수 있게 했다.

반대 방향도 쟀다. 영어 모드로 친 한국어가 고쳐져 맥락이 생긴 뒤에는 `분석부터 go`의 `go`를 `해`로 바꾼다.
이때 일부러 영어로 쓴 단어가 바뀌는 비율은 영어가 섞인 한국어 문장의 영어 단어 21,817개 중 0.06%→0.07%로 늘었다
(`so`→내, `dis`→얀 등 3건).

## 4. 영어와 한글이 섞인 단어

| 종류 | 예 | 실제 등장 수 | 영어 모드로 쳤을 때 | 한글 모드로 쳤을 때 |
|---|---|---|---|---|
| 영어 + 조사 | `SNS를`, `email을`, `giffen은`, `ch4가`, `rebate가` | 7,204 | 98.3% | 93.3% |
| 영어·숫자 + 한글 전체 (합성어 포함) | 위 + `LG전자`, `SK텔레콤은`, `A씨는`, `B형`, `FA컵` | 11,908 | 91.2% | 88.0% |

한글 모드에서는 Shift로 친 영어 대문자(`A`, `KT`, `ESPN`)를 영어의 확실한 증거로 본다(Shift는 이 키들의 한글을 바꾸지 않으므로).
반대로 `ㄱ씨는`, `ㅅ아파트`처럼 자음 하나 + 한국어는 기사에서 익명을 쓰는 방식이라 그대로 둔다.
못 고치는 예: `A매치`(`매치`가 영어로도 읽힘), `K리그1`(끝에 숫자), `n번방`, 사전에 없는 드문 이름.

## 5. 숫자 + 한글

한국어 시험 글의 `3개`, `1분기`, `65세`, `2024년에`처럼 숫자 바로 뒤에 한글이 붙은 단어 120,650개를 영어 모드로 쳤다고 보고 측정했다.

| 항목 | 결과 |
|---|---|
| 복원 비율 | **99.8%** |
| 영어 글의 `3rd`, `20th`, `1980s`, `10kg` 7,690개를 잘못 바꾼 수 | **0** |

숫자 뒤가 단위·조사이거나(`3개`, `6보다`), 두 글자 이상의 한글(`1차전에서`), 또는 한국어로 흔하고 영어로 흔하지 않은
한 글자(`1심`, `3루`)면 고친다. `th`(소), `cm`(츠), `am`(므)처럼 숫자 뒤 영어가 우연히 완전한 한글이 되는 경우는
목록(`Data/number-suffixes-en.txt`)으로 영어에 둔다. `ch4`(챕터 4), `mp3`처럼 숫자 앞 영문은 코드로 보되,
`제2차`, `고3`처럼 숫자 앞에 오는 한국어(`Data/number-prefixes.txt`)는 고친다.

## 7. 앱이 못 고치는 것 찾기 (실패 분석)

기본 시험 40만 문장의 **모든 단어**를 잘못된 모드로 쳤다고 보고, 복원에 실패한 것을 모양별로 묶었다. 지금 남은 주요 실패:

| 한국어를 영어 모드로 | 예 | 전체 단어 중 |
|---|---|---|
| 한국어로도 영어로도 말이 되는 한 글자 | `내`, `해`, `새` | 0.25% |
| 영문 + 한글 합성어 | `A매치`, `B조`, `kg당` | 0.05% |
| 괄호 안 영어 | `중동호흡기증후군(MERS`, `양해각서(MOU)를` | 0.06% |

| 영어를 한글 모드로 | 예 | 전체 단어 중 |
|---|---|---|
| 짧은 단어 | `to`, `a`, `an`, `so` (맥락 모드가 일부 해결) | 7.0% |
| 숫자 + 영어 | `20th`, `1980s` (`20소`가 한국어일 수 있어 일부러 둠) | 0.16% |
| 애매한 부분이 있는 하이픈 단어 | `so-called`, `co-founder` | 0.10% |

이 과정에서 생긴 오변환도 측정으로 잡아 되돌렸다:
`British`→`B갸샤노`, `Upwork`→`Up재가`, `추가됩니다`→`cn가됩니다`, 아이디 `rlaalswn12`→`김민주12`, 비밀번호형 문자열,
`BioLargo`→`BioLar해`, `CEO들의`→`CEOemf의`, `quantity가`→`벼무샤쇼가`, `갯녹음`→`rot녹음`, `4chan`→`4초무`.

## 8. 두 언어 모두 말이 안 되는 입력

무작위 문자열 10만 개씩.

| 입력 | 변환된 비율 | 설명 |
|---|---|---|
| 아이디처럼 영문+숫자 (`user123`) | **0%** | 영문 뒤에 숫자로 끝나면 판단하지 않음 |
| 비밀번호처럼 대소문자·숫자·기호 | **0.8%** | 비밀번호 칸에서는 아예 기록하지 않음 |
| 무작위 소문자, 영어 모드 | 2.7% | 우연히 완전한 한글 음절이 되는 경우 |
| 무작위 키, 한글 모드 | 5.7% | 영어로 읽었을 때 사전에 있는 조각이면 바뀜 |
| 무작위 한글 음절 조합을 영어 모드로 | 99.87% | 새 단어와 구별할 수 없어서 바꿈 |

추가로, 로그인 화면처럼 **칸에 단어 하나만 치고 Enter**를 누르면 바뀔 결과가 흔한 말(`다음`, `네`, `감사합니다`)일 때만 바꾼다.
채팅에서 한 단어로 보내는 말은 바꾸고, 이름으로 만든 아이디(`rlaalswn`→`김민주`)는 그대로 둔다.

## 9. Ctrl+Space 정확도

| 데이터 | 문장 | 정확히 복원 |
|---|---|---|
| 영어 뉴스 / 위키백과 (키보드로 칠 수 있는 문장) | 65,963 / 92,306 | 100% |
| 한국어 웹 / 뉴스 | 100,000 / 100,000 | 83.1% / 85.2% (키로 다시 칠 수 있는 문장 중 **100%**) |

한국어의 나머지는 `좋네요ㅋ`(같은 키를 치면 IME가 `좋네욬`으로 합침)처럼 원문 자체를 키로 재현할 수 없는 문장이다.

## 11. 속도와 메모리

| 항목 | 값 |
|---|---|
| 단어 하나 판단 | 0.3–1.0µs |
| 단어 사전·이름 목록 불러오기 | 약 0.3초 (프로그램 시작 직후 백그라운드) |
| 메모리 | 단어 사전 16MB (영어 47.8만 + 한국어 48.7만 단어) + 이름 목록 66만 개를 블룸 필터로 약 1MB |
| 터미널(cmd, PowerShell, Windows Terminal) | 바꿀 때 Backspace·글자·Enter를 나눠 보내 약 0.15초 (붙여넣기로 오인되지 않게) |

## 12. 한계

1. 문장 첫 단어가 멀쩡한 한국어이면서 영어로도 흔한 말이면(`내`=so) 맥락이 시작되지 않는다. 이런 문장은 Ctrl+Space가 확실하다.
2. 영문 + 긴 합성어 일부(`A매치`), 괄호 속 영어(`(MERS`), 한 글자로 두 언어 모두 말이 되는 `내`·`해`·`새`는 아직 못 고친다.
3. 실제 사용자 타이핑 기록이 아니라 시뮬레이션이다. 채팅체 한국어는 웹 코퍼스에 일부만 들어 있다.
   사용자가 알려 준 사례는 `tests/HanYeong.Tests/reported-cases.tsv`에 모아 앱 전체 동작으로 매번 확인한다.
